- Post-quantum JOSE signatures (RFC 9964). `[jose] post_quantum_only = true` in the server's and the sync service's configuration verifies access tokens (and DPoP proofs on the server) with ML-DSA-44, ML-DSA-65 or ML-DSA-87 alone: every issuer `algorithms` list and `[auth.dpop] algorithms` left at the default becomes the three ML-DSA parameter sets, and a list naming another algorithm stops the start. The console's sign-in now accepts an ID Token signed with ML-DSA beside the classical algorithms, and its own `[jose] post_quantum_only = true` accepts ML-DSA alone. The sync page shows a `private_key_jwt` client with an ML-DSA-65 key. The post-quantum inventory states what `ferrohealth-smart` 0.35.0 accepts and signs on each JOSE row (an ML-DSA parameter set is accepted only where an algorithm list names it), counts those rows in the post-quantum configuration, and cites RFC 9881 and draft-ietf-tls-mldsa-06 for the TLS certificate row.
