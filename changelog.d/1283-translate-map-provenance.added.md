- A `ConceptMap`'s `Provenance` (who validated the map, and when) reads by the map's canonical: `GET {base}/Provenance?target=<url|version>` answers a `searchset` of every `Provenance` whose `target.reference` is that canonical, and `Provenance/{id}` reads one. The server keeps the `Provenance` resources of every package directory it loads, `ferroterm-build --fhir-package` keeps them on import, and a deployment with a resource database accepts them over the REST API like the terminology resources, behind the same SMART write scopes. Every `$translate` match names its map as `url|version`, so a receiver records which mapping version produced a code (draft EEHRxF implementing act Art 6(3)).
