- A FHIR code system whose concepts name no parent, with `hierarchyMeaning` absent or `is-a`, is now served as an is-a hierarchy with no edges. The hierarchy filter operators answer over it as the FHIR filter-operator definitions read: `concept is-not-a X` selects every code but `X`, and `is-a X` selects `X`. `$subsumes` answers too, where these systems used to refuse every hierarchy operator. The terminology capabilities declare those operators for such systems. The tx-ecosystem suite passes `ec-vs-expand-is-not-a` and `ec-vs-validate-is-not-a-undefined` on every surface.
