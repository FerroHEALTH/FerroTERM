- ICD-11 postcoordination expressions follow the grammar and normal form of the HL7 terminology ecosystem IG's ICD-11 page. The first code is the root, `&` qualifies the code before it, every `/` member qualifies the root, and a `/` before `other` or `unspecified` is part of a residual's id (`344162786/other&1088044739/916407020`). The normal form, which is the expression's code, puts each qualifier group in the order its code declares its axes and by entity id within an axis, puts the `/` members the same way against the root's axes with those on no axis last, deletes duplicates, and keeps `/`, `&` and ICF's `.` as written. Which axis a code binds to is decided in entity id order, so the normal form does not depend on the order written. `$validate-code` answers an expression written out of order with its normal form as `normalized-code`, and warns when an axis that takes one value is given several. The display renders the expression as written, duplicates kept. `$lookup` answers `stem` as a `Coding`, and one `postcoordination` property per axis of the root that has a value, with an `axis` and its `value` Codings as subproperties, plus one for the members on no axis of the root. The tx-ecosystem `icd-11` mode passes 27 of 145, up from 25. In the `fhir-terminology` crate, `Property::value` is an `Option`, since a property may carry only subproperties.
