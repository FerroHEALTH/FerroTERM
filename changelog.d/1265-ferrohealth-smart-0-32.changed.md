- Breaking: FerroTERM moves to `ferrohealth-smart` 0.32, with `ferrohealth-session` 0.27, `ferrohealth-server` 0.11, FerroUI 0.6.11 and `ferrobridge-term` 0.16. In the server and the sync service every issuer is a named table, `[auth.issuer.<name>]`, in place of the `[[auth.issuer]]` array: `described_issuer` names an issuer by that name, a key of a named issuer can be set as `FERROTERM__AUTH__ISSUER__<NAME>__<KEY>`, and `scopeless_subjects` moves under its issuer as a list of `sub` values. An issuer's `profile = "…"` is now `preset = "…"`, and its profile keys (`first_party_clients`, `delegates`, `act_represents_patient`, `token_types` and the rest) move into its `[auth.issuer.<name>.profile]` table. Every `401` and `403` challenge now carries the refusal's stable reason code as `error_description` (RFC 6750 §3), such as `expired` or `scope-not-granted`; the `OperationOutcome` stays the same for every invalid token. A request past `server.max_concurrent_requests` now waits up to `server.admission_wait` (100 ms by default) in a queue of at most `server.max_waiting_requests` places (256 by default) before it is answered `503`, and the server's metrics count the waits and the refusals.
